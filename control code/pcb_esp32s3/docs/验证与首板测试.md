硬件RMT采用停通道、填硬件内存、重启的非阻塞更新方式，避免在持续循环输出时等待发送结束信号。停机强制idle LOW，驱动关闭时无条件停所有已配置通道。BLE应答按20字节分片并节流，USB发送等待限制10ms，防止通信发送长期占住控制循环。软件看门狗在正常控制循环下1秒无有效心跳/指令停车；控制任务若卡死，另有3秒任务看门狗复位作为后备，不把后备响应时间说成1秒。

## 样板到货后逐步验证

1. 按采购收货表清点并完成自焊。断电检查短路、方向、焊盘桥连、散热焊盘和端子接线；不要先接电机试错。
2. 只接Type-C：检查3.3V及USB枚举，按BOOT/RESET烧录。运行STATUS应为未解锁、speed全0；只接USB时A1应报NO_EXTERNAL_POWER。即使程序要求运动，也不能让USB承担电机供电。
3. 断电连接外部电源，限流首次上电，核对5V_EXT、SYS_RAW、3.3V和供电切换。GPIO2是外部5V选择状态，不是实测24V；若异常先查供电，勿修改代码绕过。
4. 上位机先status，暂不A1。默认PWM在未使能时也已设置，可测四路VREF：500mA名义设定预期约0.66V；允许器件误差，按TI公式复核，不把万用表读到的PWM引脚平均值直接当VREF或真实绕组电流。
5. 电机脱离导管负载，断电核对并接好全部四个电机的J11/J21/J31/J41后再上电。驱动有开路检测，不能只接一只电机、其余三路悬空就解锁四路。按 `jog --motor N --speed 400 --duration 0.5`核对编号、线圈和方向。若方向与机械前进定义不符，断电后核对线序，再调整FORWARD_HIGH并重编译。不要带电拔插电机。
6. 四路低速联动：确认上组M1/M3与下组M2/M4反向，同一正速度确实使导管前进；再确认负速回退。S后观察保持力；A0后明确无电气保持。
7. 通信失联测试：先低速空载，再断开USB/终止上位机，或断BLE，观察停车而不自动重启；恢复后应重新A1。普通S保持与故障/掉电释放不是相同动作。
8. BLE先近距离，再逐步到10m；测试键盘、手柄、断线、USB/BLE抢占及多块板显式选择。手机/平板的GATT客户端可发送同一协议，但本项目未交付原生移动App；各平台兼容与权限需实测。
9. 逐级增加速度并记录CSV；测电机及驱动温度，完成30～60分钟运行及静止保持两种工况。无反馈的开环步进可能失步，需同时核对实际机械运动；CSV步频是命令值。
10. 通过后才安排旧板到新板的正式切换和后续自动化控制迭代。保留原Nano与旧程序，暂不删除、覆盖或替换。

## 复测命令（不驱动实物）

在pcb_esp32s3目录：

```sh
clang++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/include tests/controller_test.cpp -o /tmp/pcb_controller_test
/tmp/pcb_controller_test
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/check_pinmap.py "../../../03_PCB_design/pin_connections.csv"
make -C host_macos demo
```

引脚检查也可以直接传入项目03中pin_connections.csv的绝对路径。串口伪终端联调另需先把 `tests/controller_sim.cpp` 编译成 `tests/controller_sim`，安装pyserial，再运行 `python tests/serial_integration.py`。此联调只使用系统伪终端，不访问任何真实串口设备。
