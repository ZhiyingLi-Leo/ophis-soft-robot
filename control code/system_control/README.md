# macOS 导管系统控制

统一操作四电机推进器与三个因时电缸。推进器可选择旧Nano或ESP32-S3 PCB；电缸以毫米位移控制。导管角度与位移的关系需要实验标定，程序不输出估计角度。

## 编译与运行

在本目录执行，要求macOS与Xcode Command Line Tools，不需要额外C++库：

```sh
make
make demo
make test
```

`make demo`自动演示正向、反向、三电缸同时移动与停止。`make test`运行C++测试和Python标准库伪终端联调，只打开测试生成的PTY，不访问真实串口。

不提供`--config`时全部为模拟设备。先用实际蓝牙手柄检查输入：

```sh
./build/robot_control --mode gamepad --duration 20
./build/robot_control --mode keyboard
./build/robot_control --mode demo --propulsion pcb --record /tmp/robot_demo.csv
```

CSV必须使用不存在的文件名；父目录需存在。`--mode demo`拒绝硬件配置。两种模拟推进器选择只能验证上层控制，不模拟驱动电路、USB供电或真实步进脉冲。

## 仅电缸控制

设置 `propulsion=none` 时仅启动三个电缸，不创建推进器线程、不打开推进器串口；三个电缸反馈正常即可启用。三轴仍须全部连接并就绪。推进输入被忽略，电缸行程、速度、反馈超时及停止规则不变。

先运行纯模拟：

```sh
make
./build/robot_control --mode keyboard --propulsion none
```

实物配置与运行（在本目录执行）：

```sh
cp -n cylinders.conf.example cylinders.conf
# 编辑 cylinders.conf，保留 cylinder_port=auto，填写三个实际ID、行程、装配限位和速度
./build/robot_control --mode keyboard --config cylinders.conf
```

`propulsion_port` 必须省略。模板包含 ID1/2/3、16 mm 行程、0–16 mm 限位和 0.5 mm/s 速度上限，必须按实物确认。模板中 `auto_zero=false`，启动不自动回零；按 `e` 启用手动操作。`1/2`、`3/4`、`5/6` 分别增加/减少三个电缸的位置目标，`空格/x` 停止并撤销启用，`q` 退出。正负方向是电缸位置增减，需现场确认对应注液或回抽。键盘是短时点动，最多延续150ms；终端显示实测位置（mm）。

手柄可将命令中的 `--mode keyboard` 改成 `--mode gamepad`，沿用下方电缸按键映射。需要记录时添加 `--record /tmp/cylinders_session.csv`，文件必须不存在。CSV的 `propulsion_ready=0` 和零推进速度表示推进器未启用，不影响独立模式就绪。

导管连接后应依据装配设置小范围、低速参数。停止不回零、不自动卸压；暂停后的负载保持能力仍需实物确认。支持点动及下述三轴绝对位置命令；摄像头测角尚未接入。

## 自动识别电缸串口

独立电缸模板使用 `cylinder_port=auto`。每次启动扫描Mac的USB串口，以配置的波特率向三个电缸ID发送 `0x30` 状态查询；只有三轴均返回有效状态才认定为电缸总线。终端显示 `Detected cylinder port: ...`，不依赖USB插口编号。

识别过程不写寄存器、不使能、不回零。唯一匹配后进入正常启动流程，`auto_zero=true` 才会在三轴就绪后自动回零。没有匹配或有多条匹配总线时退出并给出诊断，不自动选择第一条；也不会在运行中断线后自动重连并运动。可用具体的 `cylinder_port=/dev/cu.…` 路径指定设备。

扫描排除蓝牙、调试串口及已配置的推进器串口。仍需填写正确的电缸ID、波特率、行程和装配限位；这些机械参数不能从USB串口名称推断。

## 零位反馈容差

`zero_tolerance_mm` 默认0，允许设置0–0.05 mm。当前实物配置设为0.05 mm，用于容纳已观察到的−0.040 mm、−0.016 mm零位附近反馈；其物理原因和实际测量精度尚未验证。

只有装配最小位置为0时，反馈下限允许到 `-zero_tolerance_mm`；上限及所有目标位置仍严格遵守装配范围，不能发送负位置目标。实际反馈与CSV不被改写为0。回零到位按绝对反馈不超过容差判断；负偏差轴在容差内时不再向负方向运动。运动目标从合法范围内生成，反馈进一步越界仍停止。`move 0 0 0` 的到位判断同样使用零位容差，非零目标维持原有位置码精度判定。

## 只读检查

```sh
./build/robot_control --mode inspect --config cylinders.conf
```

仅查询三轴状态，输出原始位置码、原始目标码、按配置行程换算的位置及装配范围。此模式忽略自动回零，不创建运动工作线程、不发送寄存器写入。即使某轴位置越界，也继续读取其他轴并以非零退出码报告异常。可用于排查启动位置越界；不要通过扩大装配范围或修改位置换算来掩盖尚未确定原因的异常反馈。

## 三轴绝对位置命令

完成 `cylinders.conf` 的实际参数配置后，在本目录启动：

```sh
./build/robot_control --mode command --config cylinders.conf --record /tmp/cylinder_calibration_001.csv
```

CSV文件须不存在。此模式仅支持 `propulsion=none`。模拟体验（不连接硬件）：

```sh
./build/robot_control --mode command --propulsion none
```

等待自动回零完成（未启用回零时等待 `ready=1`），输入以下命令，每行回车执行：

```text
enable
move 1.0 2.0 1.5
move 2.0 2.0 2.0
move 0 0 0
stop
quit
```

三个数字依次为电缸1、2、3的绝对位置，单位mm，不是增量。示例数值须位于实际配置的装配限位内。每次发出 `move` 后等待终端显示 `Reached target`，观察导管稳定后再拍摄和发下一组目标；无需持续按键。程序依据电缸位置码分辨率量化目标，显示到位只代表三轴编码反馈符合量化后的目标，不代表导管形状已稳定。

- `enable`：启用；回零过程中提交的位置命令会被拒绝，不排队。
- `move X1 X2 X3`：按各轴配置速度和前瞻限制逐步移动，新目标替换旧目标；三轴通过串口依次通信，不保证同时到达。
- 到位后继续保持位置命令，便于拍摄；负载下的实际保持性能需实测。超时上限沿用回零的行程/速度估算，超时停止退出。
- `stop` + 回车：暂停并撤销启用；Esc不需要回车即可停止。继续运动需重新 `enable`，再发送 `move`。
- `quit` + 回车或Ctrl-C：停止并退出。
- 越界、非数值或格式错误的命令会停止并撤销启用，不会部分执行三个目标。输入时空格用作参数分隔，不作为停止键；点动键只在 `keyboard` 模式使用。

CSV持续记录时间、实际位置、逐步下发的目标及反馈年龄，可用于与摄像头数据对照；当前没有相机触发或相机时间同步。

## 操作

### 蓝牙手柄

先在macOS系统设置中配对。程序优先读取GameController，必要时回退到IOKit HID；后者可能需要为运行程序的终端授予“输入监控”权限。无需编写Bluetooth传输协议。

| 输入 | 行为 |
|---|---|
| 摇杆回中、松开L1，按A | 启用操作；不回零、不立即运动 |
| 按住L1＋右摇杆水平 | 推进器正向/反向，带死区与加减速 |
| 按住L1＋左摇杆水平 | 电缸1目标位移增减 |
| 按住L1＋左摇杆垂直 | 电缸2目标位移增减 |
| 按住L1＋右摇杆垂直 | 电缸3目标位移增减 |
| 松开L1 | 停推进；已由本程序驱动的电缸发送暂停 |
| Options/Back | 停止并撤销启用；需回中后重新按A |
| Ctrl-C | 请求各设备停止、关闭串口并退出 |

多轴可以同时操作；这里的三轴协调表示同时管理三个电缸目标，不表示已实现目标弯曲角度控制或硬件同步。

HID映射沿用T4n Lite兼容路径：X/Y、Rx/Ry，右摇杆缺失时尝试Z/Rz；A/L1/Options为按钮usage 1/5/7。GameController与HID的上下方向可能不同，需在模拟运行中观察确认。缺少任一轴或操作按键时不允许运动。程序不自动切换已经选中的手柄；多个设备同时连接会提示，换手柄或设备重新枚举后应退出重启。

### 键盘

`e`启用，`a/d`推进，`1/2`电缸1，`3/4`电缸2，`5/6`电缸3；每对按键分别增加/减少目标位移。`空格/x`停止并撤销启用，`q`退出。

终端无法可靠提供按键释放事件，因此每次方向键输入仅维持最多150ms，持续按键由系统重复输入续期。它是短时点动方式，不能等同游戏手柄的连续按住检测。键盘一次控制一个方向，手柄支持多轴同时输入。

## 实物配置

将`hardware.conf.example`复制为`hardware.conf`，填入两条实际串口和三个电缸的独立参数：

```text
propulsion=nano
propulsion_port=/dev/cu.实际推进器端口
cylinder_port=/dev/cu.实际电缸总线端口
cylinder_baud=115200
max_speed=3200
acceleration=3200
deadzone=0.12
cylinder1=ID,本体总行程mm,装配最小位置mm,装配最大位置mm,最大速度mm/s
cylinder2=ID,本体总行程mm,装配最小位置mm,装配最大位置mm,最大速度mm/s
cylinder3=ID,本体总行程mm,装配最小位置mm,装配最大位置mm,最大速度mm/s
```

参数行必须替换为实际数值。三个ID必须不同，各轴本体行程、装配限位和速度分别设置，不依据旧源码中的16/30/50mm推断。全行程为2000位置码；位置取最近可用码并限制在装配范围，最大速度向下取整，避免编码后超过配置速度。速度分辨率不足一个位置码/秒时拒绝配置。配置文件中未知键、重复键及缺失值均报错。

选择新PCB时改为`propulsion=pcb`和对应原生USB串口，其他操作不变。程序通过USB控制推进器；蓝牙只用于手柄。原PCB Python工具的BLE板端控制继续独立保留。

完成现场接线、供电及机械空间确认后，实物入口为：

```sh
./build/robot_control --mode gamepad --config hardware.conf --record /tmp/robot_hardware.csv
```

启动读取电缸状态并以实际位置作为目标起点。默认 `auto_zero=false` 时不使能电缸、不回零、不自动写位置；启用 `auto_zero=true` 后按下述规则自动回零，不修改电缸硬件零点。Nano初始化发送停止，新PCB不在启动时解锁。联合模式只有三个电缸及推进器均就绪，才接受启用；`propulsion=none` 只要求三个电缸就绪。不要同时运行其他占用这些串口的程序。

实际位置超出装配范围时程序报错退出，不自动把它拉回范围。应先现场处理装配及位置。停止不自动卸压或回到零位。

## 连接后自动回零

在硬件配置中设置 `auto_zero=true`，启动程序后读取三轴位置，全部就绪后自动向电缸自身的绝对 `0 mm` 移动。仓库模板默认关闭；本机已有配置可能开启，启动前应检查实际文件。联合模式还需等待推进器就绪，回零期间推进命令为零。

- 三轴的装配最小位置必须为 `0`，否则在打开串口前拒绝配置；不会绕过装配限位。
- 使用各轴配置中的最大速度逐步递减目标，保留位置前瞻限制、通信检查及250ms输入失效停止。请按已连接导管的工况填写低速值。
- 回零期间终端显示 `homing=1`，CSV增加 `homing` 列。只有三轴反馈均处于配置的零位容差内才显示完成（默认容差为0）；不以“已发送命令”判定到位。
- `空格/x`、手柄停止键、输入设备断开或就绪状态丢失会取消本次回零；`q`、Ctrl-C退出并请求停止。取消后不自动重试，重新启动程序才会再次自动回零。
- 回零完成或取消后保持手动操作未启用，需按 `e` 或手柄A重新启用。完成时对已驱动轴发送暂停；暂停不代表刚性保持或自动卸压。
- 超时上限取三轴中最大的 `10 + 4 × 本体行程 / 配置速度` 秒；超时或设备故障停止并退出，不继续尝试回零。

这是程序连接后的自动位置运动，不是插入USB即运行，也不是硬件寻零或重设编码器零点。实机回零精度、机械停止和液压响应仍需现场验证。

## 通信异常诊断

电缸运动期间循环间隔20ms，未启用运动时为100ms（均另加串口事务耗时）。状态查询仍采用150ms应答超时，不自动重发运动指令；通信异常仍停止并退出。

超时报错包括请求命令、地址、收到的字节数及最多64字节十六进制回包。`no_bytes` 表示没有收到数据，`short_reply` 表示收到的数据不足完整状态帧，`no_matching_valid_frame` 表示数据未通过完整的ID、命令、地址及校验验证。单次超时不能直接判断为硬件故障或单纯丢包。

## 控制与通信

- 推进器与三电缸总线各有一个工作线程；同一串口请求/回复串行执行。主线程处理输入与系统状态，不等待电缸到位。
- 操作请求仅保留最新值，停止请求单独保留，避免快速停止/重新启用使停止被覆盖。输入更新超过250ms时工作线程停止本程序的运动。该检查依赖工作线程仍在运行；不是操作系统实时保证。
- Nano使用`?`及`V<step/s>`；新PCB先检查`INFO PCB1_S3`，按需`A1`，每100ms或速度变化时发送带应答的V指令维持通信，停止时`V0/A0`。不绕过PCB原有外部电源、故障、所有权与板端看门狗保护。
- 电缸查询使用`0x30`；验证20字节状态回复的帧头、长度、ID、命令、地址和校验和。位置写入用旧项目已有的`0x32/0x25`模式2、速度和位置寄存器；暂停用`0x32/0x1A`。
- 通信失败或电缸故障会终止当前会话，停止其他子系统，不自动重发运动或清故障。运动写入前就记录停止责任，避免“命令已到达、回复丢失”漏发停止。每个已操作轴分别尝试暂停，一轴超时不跳过其他轴。
- 电缸目标增量受速度、实际位置附近的前瞻距离及装配限位约束，避免串口延迟积累很远的待执行目标。此处控制的是目标位移变化率，真实运动速度需实测。
- 串口写等待有100ms上限，推进器应答约200ms、电缸应答约150ms超时。三电缸为依次请求；停止可能等待当前事务结束，再分别发送暂停，不声称三轴同步或立即机械停止。

## 现有硬件限制

Nano原固件没有通信超时停车。正常运行时本程序检测输入异常并发送V0，但主机崩溃、进程被强制杀死或物理断线后，不能保证旧Nano停止持续脉冲。上位机测试不能消除此限制；实物应保留独立停机手段。固件位于相邻 `nano_firmware/arduino/propulsion_controller/`，本目录未修改它。

电缸暂停通常禁止功率输出，不能理解为液压负载下的刚性保持；松开L1及退出后的机械行为需现场验证。摇杆回中但继续按住L1时保留最后位置目标；这与发送暂停不同。状态回复仅证明通信与数字反馈，不证明装配安全或到位精度。

电缸驱动针对旧项目所附V2.03状态/寄存器协议；三个实物的固件兼容性、供电、接口、总线连接和回复形式必须核对。无有效回复时退出，不自动尝试其他运动协议。

## 文件分工

| 文件 | 职责 |
|---|---|
| `include/robot.hpp` | 配置、输入、控制请求、状态及系统调用 |
| `src/config.cpp` | 配置检查、单位换算、死区和加减速 |
| `src/protocol.cpp` | 电缸组帧与状态解析 |
| `src/serial.cpp` | 有限等待的串口通信与请求/回复 |
| `src/system.cpp` | 两个设备工作线程、推进后端、三电缸位移调度及停止 |
| `src/gamepad.mm` | 苹果GameController/HID适配，C++与Objective-C交界 |
| `src/keyboard.cpp` | 终端短时点动 |
| `src/main.cpp` | 操作入口、启停协调、状态显示与CSV |
| `tests/` | 控制边界及伪终端联合测试 |

CSV记录推进命令步频、电缸实际位置、目标位移、设备就绪及各轴反馈年龄；没有角度或末端力。`simulation`区分模拟与实物；年龄为-1表示尚未读取。记录为主机采样快照，三轴反馈来自不同请求，不是硬件同步测量；推进步频也不是编码器速度。
