# 本地系统控制台

## 启动

在项目根目录执行（使用工作台独立 Python 环境；渲染库已随项目附带，运行不访问 CDN）：

```sh
"control code/local_dashboard/.venv/bin/python" "control code/local_dashboard/server.py"
```

浏览器打开 http://127.0.0.1:8765 。服务只监听本机。Ctrl-C停止服务并请求停止设备。端口占用时使用 `--port 8766`。

网页仅提供真实硬件模式；服务启动不枚举或打开真实串口。网页不执行旧命令行配置中的自动回零。真实硬件必须由操作者扫描并主动接入后使用，不与旧串口程序同时运行。

## 使用

1. 点击“扫描设备”，进入液压驱动页面，任选一个电缸点击“接入”。其余模块无需连接。
2. 点击该轴“启用”，设置绝对位置后点击“移动”；也可点击 ±0.1 mm 做相对位移。
3. 位置、目标、速度、温度和反馈年龄分别显示；真实CAD模型中的滑块和推杆根据实际反馈作位移示意。拖动旋转、滚轮缩放，点击电缸可选择对应卡片。
4. 三轴全部连接并启用后，才允许三轴协同目标；目标会整体校验，越界不会部分执行。串口依次通信，不是三轴硬件同步。
5. 推进器可以独立接入。M1–M4 可独立设置 0–1600 step/s，点击前进/后退持续运行，点击停止结束；统一控制同样支持速度设置。电缸到位后保留目标控制，点击停止会暂停并撤销启用。
6. Esc或“全部停止”请求停止所有模块。浏览器切到后台/窗口失焦不会主动停机；1.5秒控制心跳失效后后台停止并撤销启用。推进器另有350ms命令续期要求。以上是上位机保护，不代替硬件断电停止和板端看门狗。

## 真实设备与自动识别

点击“扫描设备”开始识别。检测Mac USB串口，对配置中的三个电缸ID分别发只读查询，识别推进器PCB的INFO或Nano的速度查询回复。只找到一个电缸也能识别总线、独立连接该轴。多条总线匹配时需选择具体总线；不会任意选择第一条。

首次扫描后，未启用运动时检测USB串口列表变化并自动重新识别。扫描不会发运动/寄存器写入，但打开Nano串口可能触发其硬件复位。已启用模块时拒绝新扫描。识别和接入是不同步骤；插拔后不自动连接、不恢复旧目标。故障轴需主动重新连接并启用。

网页沿用 `../system_control/cylinders.conf` 中的ID、行程、装配限位、速度、波特率和零位容差。忽略其推进器端口选择及自动回零设置。默认三个ID 1/2/3、16mm行程、0–16mm装配范围、0.5mm/s，现场仍须按机械装配确认限位。

- 通信故障停止该轴所在总线上的已驱动轴，其他独立总线/推进器继续保持自己的状态。共享总线不能视为相互独立的电气故障域。
- 不自动重发运动指令；暂停回复丢失时明确显示“停止未确认”。停止不是卸压或刚性保持。
- PCB保留原固件的故障、解锁及看门狗机制。Nano原固件没有断线自动停止保证；主机崩溃或断线时必须有现场独立停机手段。
- 浏览器只允许一个控制会话，其他页面可查看/请求全部停止；活跃会话释放后才能接管。

## 模型与相机

界面加载项目 `3d model/` 中的电缸、滚轮推进器和 D405 支架 GLB。总览与俯视显示支架，点击支架可进入实验台。支架相对导管的位置为布局示意。提供总览、液压组件、推进组件和俯视；支持旋转、缩放、平移与点击选择电缸。

GLB按米加载、位移以毫米换算。液压装配从原始−Z方向映射到画面推进方向，电缸按原模型X坐标从小到大映射ID 1/2/3，工作站视图从上到下为 ID 3/2/1；滑块与推杆沿原始−Z移动。内部 ID 已与该上下排列对应，模型仍不用于确定装配零位和安全限位。注射器颜色仅为材质显示，不代表液量测量。

液路、末端弯曲导管及半透明气道为结构示意，不随电缸数据生成未经标定的弯曲结果。实验台显示实时预览、侧视二维弯曲角和 D405 未标定的三维表面角；装配模型不据此生成未经验证的末端形变。

界面设计要求见 [DESIGN_PROMPT.md](DESIGN_PROMPT.md)。渲染采用本地附带的Three.js r170（MIT），许可见 `static/vendor/LICENSE.three`，来源与文档见 `static/vendor/README.md`。

D405 已作为独立插件接入，提供采集、无标记轮廓提取、预览与文件记录。SDK 缺失或相机不在线不影响手动电缸控制。安装、脚本和验证范围见 [CAMERA.md](CAMERA.md)。

## 文件

- `server.py`：本机HTTP服务、设备调度、状态、串口协议、配置加载。
- `static/app.js`：控制界面和状态绑定。
- `static/scene.js`：真实GLB装配、材质、视角、模型选择和位移示意。
- `static/vendor/`：本地Three.js依赖与MIT许可，无运行时外部网络资源。
- `test_server.py`：模拟设备与PTY串口测试；不打开真实串口。

```sh
PYTHONDONTWRITEBYTECODE=1 "control code/local_dashboard/.venv/bin/python" -m unittest discover -s "control code/local_dashboard" -p "test_*.py" -v
```

已验证独立接入、位置移动、目标校验、会话失效停止、推进点动超时、共享总线故障处理、部分轴识别/歧义处理、回显与碎片回包，以及HTTP同源限制。电缸通信已有实机检查记录；D405 驱动和视觉测量仍待相机到位后联调，自动测试不代表相机实测精度。

## 工作区与逐模块状态

侧栏提供「系统总览」「液压驱动」「滚轮推进器」和「实验台」，也可连接或退出手柄控制。总览显示三维装配及三个模块的状态。三维视图标注各电缸 ID、毫米位置及连接和运动状态；无有效反馈显示破折号。

PCB 的 STATUS 四路 speed/current_ma 显示在四张电机卡片和三维状态标签中。speed 为板端脉冲频率，current_ma 为驱动电流设定，均不是传感器实测转速/电流。M1–M4 与模型位置暂作示意，须实机确认对应关系。板端故障是公共故障，不能推断是哪一台电机损坏。Nano 不提供四路遥测。PCB 支持四路独立控制，Nano 仅支持统一控制。正负方向沿用固件通道方向，现场须核对滚轮装配与接线。

设备通过 `device_plugins/` 注册为独立对象，电缸和推进器适配现有安全引擎，相机使用独立采集线程；实验脚本通过统一设备接口联调。共享总线和控制器仍有公共故障边界。

离线模拟仅供自动测试内部构造 Engine(testing=True) 使用；网页 API 不可切换模拟。

## 实验台与本机 Python 指令

「实验台」并排显示 D405 和侧视相机，下方的「实验指令与日志」提供 Pre-test、指令预设，以及 `help`、`scripts`、`clear`、`stop` 和 `python scripts/name.py [参数]`。输入框提供已有脚本的补全候选。

脚本放在本目录 `scripts/` 中，使用启动服务的 Python 解释器执行，工作目录为 `local_dashboard/`。这是本机 Python 程序，具有启动服务用户的文件与网络权限，只运行自己信任的代码；不经 shell 执行，不支持管道或任意终端命令。依赖需安装到服务使用的 Python 环境。

```sh
python scripts/status.py
python scripts/camera_check.py
python scripts/camera_record.py --seconds 30 --label reference
python scripts/sample_positions.py --help
python scripts/motor_run.py --motor 1 --speed 400 --seconds 2
```

`status.py` 读取状态；`camera_check.py` 检查环境；`camera_record.py` 记录已接入相机；`sample_positions.py --help` 查看采样参数；`motor_run.py` 会使已连接 PCB 的 M1 正向运行 2 秒。负速度为反向。先在网页扫描并接入设备，脚本不会自动连接硬件。

自定义脚本通过 `from experiment_api import Robot` 调用：

```python
from experiment_api import Robot
robot = Robot()
robot.arm(1)
robot.move(1, 1.0)
robot.wait_cylinder(1, timeout=30)
print(robot.state()['axes'][0]['position'])
```

`motor(1, 400)`、`stop_motor(1)` 分别启动/停止一个电机；`motors(400)`、`stop_motors()` 控制四路。`wait(seconds)` 在等待中检查通信异常。脚本不得直接打开设备串口，应使用此接口共享限位、单会话、故障和续期保护。

开始实验前停止当前运动；运行中禁止手动运动指令与脚本混用。脚本正常退出、异常退出、中止、浏览器失联或关闭服务时，均撤销脚本接口权限并请求全部设备停止。子进程使用独立进程组，中止时发送 TERM 并在 0.5 秒后补发 KILL；正常退出也清理同组子进程。不可把主动脱离进程组或直接绕过接口访问设备的脚本视为受这些保护约束。

输出只保留有限长度的内存缓冲，不作为实验数据存储；实验数据由脚本自行保存到文件。

## 手柄控制

先在 macOS 蓝牙设置中配对并连接手柄，再打开 Chrome 工作台并按任意手柄按钮完成识别。网页通过 Gamepad API 读取标准映射手柄，无需串口配置。接入所需设备，将摇杆回中，再点击手柄栏“连接”。该按钮停止原有运动并启用当前在线、反馈新鲜且无故障的电缸。各设备独立响应，未接入设备忽略输入。

| 输入 | 正方向 | 负方向 |
| --- | --- | --- |
| 左摇杆左右 | 右：四个推进电机一起前进 | 左：一起后退 |
| 左摇杆上下 | 上：ID1 伸出 | 下：ID1 回退 |
| 右摇杆左右 | 右：ID2 伸出 | 左：ID2 回退 |
| 右摇杆上下 | 上：ID3 伸出 | 下：ID3 回退 |

摇杆死区为 18%，回中停止对应通道。电缸使用各自配置的限位和速度上限；推进器最大速度使用推进器页面的“四电机统一速度”，默认 400 step/s，可设置 0–1600 step/s。B / ○、Esc 或“全部停止”停止运动；手柄栏“退出”停止本次手柄会话的设备。

手柄拔出或输入超过 0.6 秒未更新会停止手柄控制，恢复后需回中重新启用。切换窗口不主动发送停止；Chrome 在后台暂停手柄采样时仍会触发输入超时，不能用旧摇杆值持续运动。设备重连、故障恢复或手动停止不会自动恢复运动。手柄控制与实验脚本互斥；运行脚本会退出手柄控制。

软件测试使用模拟设备，不连接真实串口。实际手柄兼容性、实物运动方向和速度需逐轴核对。
